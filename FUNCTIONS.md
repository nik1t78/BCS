# 📚 Полное руководство по функциям ВКС Расписание

## 🎯 Обзор системы

ВКС Расписание — это полнофункциональная система управления видеоконференциями с ролевой моделью доступа, уведомлениями и интеграциями.

---

## 📋 Список всех функций

### 🔐 Авторизация и безопасность

#### 1. Регистрация пользователей
- **Описание**: Создание нового аккаунта
- **Доступ**: Публичный
- **Поля**: ФИО, Email, Пароль, Телефон, Отдел
- **Валидация**: Уникальный email, пароль от 6 символов
- **API**: `POST /api/auth/register`

#### 2. Вход в систему
- **Описание**: Аутентификация пользователя
- **Доступ**: Публичный
- **Проверки**: Email/пароль, статус аккаунта (активен/заблокирован)
- **API**: `POST /api/auth/login`
- **Возвращает**: Токен доступа + данные пользователя

#### 3. Выход из системы
- **Описание**: Завершение сессии
- **Доступ**: Авторизованные пользователи
- **Действие**: Удаление токена
- **API**: `POST /api/auth/logout`

#### 4. Автоматическая блокировка
- **Описание**: Блокировка аккаунта администратором
- **Доступ**: Admin, Moderator
- **Эффект**: Пользователь не может войти
- **API**: `PUT /api/admin/users/{id}/toggle-active`

---

### 👤 Управление профилем

#### 5. Просмотр профиля
- **Описание**: Отображение личных данных
- **Доступ**: Владелец профиля
- **Данные**: ФИО, Email, Телефон, Отдел, Должность, Аватар
- **API**: `GET /api/auth/user`

#### 6. Редактирование профиля
- **Описание**: Изменение личных данных
- **Доступ**: Владелец профиля
- **Поля**: Имя, Email, Телефон, Отдел, Должность
- **API**: `PUT /api/profile`

#### 7. Смена пароля
- **Описание**: Изменение пароля с проверкой текущего
- **Доступ**: Владелец профиля
- **Проверка**: Текущий пароль должен совпадать
- **API**: `POST /api/profile/change-password`

#### 8. Настройки уведомлений
- **Описание**: Персональные настройки уведомлений
- **Параметры**:
  - Звуковые уведомления (вкл/выкл)
  - Браузерные уведомления (вкл/выкл)
  - Время напоминания по умолчанию (5-1440 мин)
  - Рабочие часы (начало/конец)
  - Часовой пояс
- **API**: `GET/PUT /api/settings`

### 📅 Управление конференциями

#### 9. Создание конференции
- **Описание**: Планирование новой видеоконференции
- **Доступ**: Все пользователи
- **Поля**:
  - Название (обязательно)
  - Описание
  - Дата и время начала/окончания
  - Комната/переговорная
  - Ссылка на ВКС (Zoom, Teams, etc.)
  - Приоритет (низкий/средний/высокий)
  - Напоминание за N минут
  - Повторение (ежедневно/еженедельно/ежемесячно)
  - Участники (пользователи системы)
  - Внешние участники (email)
  - Приватность (публичная/приватная)
- **API**: `POST /api/meetings`
- **Уведомления**: Автоматическое уведомление участников

#### 10. Просмотр списка конференций
- **Описание**: Отображение всех доступных конференций
- **Доступ**: Все пользователи
- **Фильтры**:
  - По статусу (запланирована/идёт/завершена/отменена)
  - По дате
  - Только мои
  - Поиск по названию/комнате
- **API**: `GET /api/meetings`

#### 11. Просмотр деталей конференции
- **Описание**: Полная информация о конференции
- **Доступ**: Участники, организатор, админ
- **Данные**: Все поля + список участников + организатор
- **API**: `GET /api/meetings/{id}`

#### 12. Редактирование конференции
- **Описание**: Изменение параметров конференции
- **Доступ**: Организатор, Admin
- **Ограничения**: Нельзя изменить завершённую конференцию
- **API**: `PUT /api/meetings/{id}`

#### 13. Удаление конференции
- **Описание**: Удаление конференции из системы
- **Доступ**: Организатор, Admin
- **Действие**: Мягкое удаление (сохраняется в истории)
- **API**: `DELETE /api/meetings/{id}`

#### 14. Изменение статуса конференции
- **Описание**: Обновление статуса (запланирована → идёт → завершена)
- **Доступ**: Организатор, Admin, Moderator
- **Статусы**:
  - `scheduled` - Запланирована
  - `in-progress` - Идёт сейчас
  - `completed` - Завершена
  - `cancelled` - Отменена
- **API**: `PUT /api/meetings/{id}` (поле status)

#### 15. Приватные конференции
- **Описание**: Конференции видны только участникам
- **Доступ**: Организатор, участники, Admin
- **Поведение**: Не отображаются в общем списке
- **Поле**: `is_private: boolean`

#### 16. Повторяющиеся конференции
- **Описание**: Автоматическое создание серий конференций
- **Типы**:
  - `daily` - Ежедневно
  - `weekly` - Еженедельно
  - `monthly` - Ежемесячно
- **Механизм**: Scheduler создаёт новые экземпляры
- **Поле**: `recurring`

### 📊 Расписание и календарь

#### 17. Просмотр по дням
- **Описание**: Список конференций на конкретный день
- **Доступ**: Все пользователи
- **Отображение**: Хронологический список с временем
- **Навигация**: Вперёд/назад по дням

#### 18. Просмотр по неделям
- **Описание**: Сетка на 7 дней
- **Доступ**: Все пользователи
- **Отображение**: 7 колонок (Пн-Вс) с конференциями
- **Цветовая кодировка**: По приоритету

#### 19. Просмотр по месяцам
- **Описание**: Календарная сетка на месяц
- **Доступ**: Все пользователи
- **Отображение**: Сетка дней с количеством конференций
- **Навигация**: Вперёд/назад по месяцам

#### 20. Фильтры расписания
- **Описание**: Фильтрация отображаемых конференций
- **Фильтры**:
  - Все конференции
  - Только мои (участник или организатор)
  - Сегодня
  - Ближайшие (будущие)
- **Комбинация**: Можно комбинировать с поиском

#### 21. Экспорт расписания
- **Описание**: Выгрузка расписания во внешние форматы
- **Форматы**:
  - **ICS** - Для импорта в Google Calendar, Outlook, Apple Calendar
  - **JSON** - Для программной обработки
  - **CSV** - Для Excel и других таблиц
- **Доступ**: Все пользователи (только свои конференции)
- **API**: Клиентская функция (frontend)

### 🔔 Система уведомлений

#### 22. Напоминания о конференциях
- **Описание**: Уведомление за N минут до начала
- **Механизм**:
  - Scheduler проверяет каждую минуту
  - Создаёт уведомление если время совпадает
  - Отправляет браузерное уведомление
  - Воспроизводит звук (если включено)
- **Команда**: `php artisan meetings:send-reminders`
- **Частота**: Каждую минуту

#### 23. Уведомление о начале конференции
- **Описание**: Уведомление когда конференция начинается
- **Механизм**: Аналогично напоминанию
- **Триггер**: `start_time == current_time`
- **Тип**: `starting`

#### 24. Уведомление о добавлении в конференцию
- **Описание**: Когда вас добавили как участника
- **Триггер**: Создание/обновление конференции
- **Тип**: `user-added`
- **Сообщение**: "Вас добавили в конференцию {название}"

#### 25. Список уведомлений
- **Описание**: Просмотр всех уведомлений
- **Доступ**: Владелец уведомлений
- **Фильтры**:
  - Все
  - Непрочитанные
  - Прочитанные
  - По типу
- **API**: `GET /api/notifications`

#### 26. Отметка прочитанным
- **Описание**: Отметить уведомление как прочитанное
- **Доступ**: Владелец уведомления
- **API**: `PUT /api/notifications/{id}/read`

#### 27. Прочитать все
- **Описание**: Отметить все уведомления как прочитанные
- **Доступ**: Владелец уведомлений
- **API**: `PUT /api/notifications/read-all`

#### 28. Очистка уведомлений
- **Описание**: Удалить все уведомления
- **Доступ**: Владелец уведомлений
- **API**: `DELETE /api/notifications/clear`

#### 29. Счётчик непрочитанных
- **Описание**: Количество непрочитанных уведомлений
- **Отображение**: Бейдж в шапке сайта
- **API**: `GET /api/notifications/unread-count`
- **Обновление**: Автоматическое каждые 30 секунд

#### 30. Браузерные уведомления (Push)
- **Описание**: Системные уведомления браузера
- **Требования**: Разрешение пользователя
- **Работа**: Даже когда вкладка не активна
- **Настройка**: В профиле

#### 31. Звуковые уведомления
- **Описание**: Звуковой сигнал при уведомлении
- **Механизм**: Web Audio API
- **Настройка**: В профиле (вкл/выкл)

- **Фильтры**:
  - Поиск по имени/email/отделу

#### 33. Создание пользователя

- **Доступ**: Только Admin
- **Поля**: Все поля регистрации + роль

#### 34. Редактирование пользователя
- **Описание**: Изменение данных пользователя

- **Ограничения**: Нельзя удалить себя

#### 37. Блокировка/разблокировка

- **Доступ**: Admin, Moderator

#### 38. Просмотр деталей пользователя
- **Описание**: Полная информация о пользователе
- **Доступ**: Admin, Moderator
- **Данные**: Все поля + статистика конференций


### Настройка Nginx для production

```nginx
server {
    listen 80;

    server_name example.com;

    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    # Security headers
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;

    # Frontend
    root /var/www/frontend;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # API
    location /api/ {
        root /var/www/backend/public;
        try_files $uri /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass backend:9000;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }
}
```
