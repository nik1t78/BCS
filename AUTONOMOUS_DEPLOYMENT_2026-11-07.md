# BCS — автономная эксплуатация и восстановление после отключения питания

## Что добавлено в проект

1. **Автозапуск Windows**: `ops/windows/Start-BCS.ps1` ждёт готовности Docker Engine и запускает Compose без пересборки образов.
2. **Watchdog Windows**: `ops/windows/Watchdog-BCS.ps1` запускается Планировщиком каждые 5 минут, восстанавливает остановленные контейнеры и перезапускает unhealthy-приложения.
3. **Установка задач Windows**: `ops/windows/Install-Autostart.ps1` регистрирует запуск после входа, watchdog и ежедневную задачу копирования бэкапов.
4. **Внешняя копия БД**: `ops/windows/Copy-BCS-Backups.ps1` создаёт свежий дамп, копирует на отдельный диск/NAS только архивы с совпадающим SHA-256 и хранит 30 дней.
5. **Linux Server**: systemd unit `ops/linux/bcs.service` запускает Compose после Docker/network; timer watchdog проверяет состояние каждые 5 минут; persistent backup timer догоняет пропущенное резервное копирование после простоя.
6. **Docker healthchecks**: backend, nginx, MySQL, Redis, queue, scheduler и VKS bot имеют healthcheck; долгоживущие сервисы используют `restart: unless-stopped`.
7. **Бережное завершение**: заданы stop grace periods; MySQL настроен на `innodb_flush_log_at_trx_commit=1` и `sync_binlog=1`.
8. **Защита данных**: watchdog намеренно не делает принудительный restart MySQL только из-за unhealthy probe; при проблеме базы пишет критическое сообщение, чтобы не усугубить повреждение данных.

## Что невозможно обеспечить только программой

- Если электричество отключено, сервер без UPS не может продолжать работу.
- Чтобы компьютер сам включился после возвращения питания, нужна поддержка BIOS/UEFI `Restore on AC Power Loss` и значение `Power On`.
- Для непрерывной связи нужны UPS для сервера и сетевого оборудования, а для внешнего доступа — резервный интернет.
- Windows + Docker Desktop обычно требует входа пользователя. Безоператорная работа после включения Windows надёжнее обеспечивается Linux Server + Docker Engine + systemd.
- Единственная копия на том же физическом диске не защищает от отказа диска; настройте отдельный NAS/диск/защищённое удалённое хранилище.

## Проверки, выполненные при подготовке архива

- Docker Compose YAML разобран YAML-парсером; наличие restart policy и healthcheck проверено для всех долгоживущих сервисов.
- Shell-скрипты Linux прошли `bash -n`.
- 118 PHP-файлов прошли `php -l`.
- Python-модули VKS bot прошли `compileall`.
- Сохранены независимые правила бронирования: одинаковое время в разных залах разрешено; конфликт проверяется в рамках конкретного зала.

## Что требует проверки на целевом сервере

В текущей среде не установлены Docker Engine/Compose, Windows Task Scheduler и PowerShell runtime. Поэтому не выполнялись фактические Docker image builds, запуск контейнеров, применение миграций к MySQL, тест аварийного отключения питания, регистрация Windows Scheduled Tasks и реальное восстановление из backup. Перед эксплуатацией выполните установку по `ops/windows/README.md` или `ops/linux/README.md`, затем проверьте `docker compose ps`, логи и тестовое восстановление дампа на отдельной тестовой БД.
