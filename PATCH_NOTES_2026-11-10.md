## Исправления кода

1. `backend/app/Http/Controllers/Api/TvScreenController.php`: исправлен счётчик просмотров ТВ-экрана. Используется атомарный `increment('polls', 1, [...])`, а не вызов `increment()` у булевого результата `update()`.
2. `backend/bootstrap/app.php`: API-запросы с отсутствующим/истёкшим Sanctum-токеном возвращают HTTP 401 JSON; проверка `auth:sanctum` не ослаблена.
3. `docker-compose.yml`: миграции больше не запускаются параллельно внутри `queue` и `scheduler` с подавлением ошибок. Миграции выполняются явно при развёртывании после запуска backend; это исключает гонку двух миграционных процессов и скрытие ошибки.
4. `START-BCS-WINDOWS.ps1`: добавлен мастер первого запуска для Windows. Если `.env` отсутствует, он создаёт его из `.env.example` и генерирует уникальные `APP_KEY`, пароли MySQL и Redis. Существующий `.env` не перезаписывается. Скрипт проверяет Docker Engine, конфигурацию Compose, собирает сервисы, публикует Laravel assets, применяет миграции и создаёт storage-ссылку.
5. `README.md`: исправлены противоречивые инструкции по `APP_KEY`, добавлен рекомендуемый запуск Windows и предупреждение о демонстрационном сидере с известными паролями.

## Важные замечания перед эксплуатацией

- Для первого запуска Windows из корня папки проекта выполните: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\\START-BCS-WINDOWS.ps1`.
- Проверьте `SITE_IP` в `.env`; он должен соответствовать адресу сервера.
- Не запускайте `VksDatabaseSeeder` на рабочей базе: он создаёт демонстрационные аккаунты со стандартными паролями и тестовые конференции.
- Не выполняйте `docker compose down -v` и не удаляйте `docker/mysql/data`, `.env` или резервные копии.
- Перед заменой файлов на действующем сервере сделайте отдельную резервную копию БД и `.env`.
- Для автоматического включения после восстановления электропитания требуется `Restore on AC Power Loss = Power On` в BIOS/UEFI. Для продолжения работы при пропадании питания нужен UPS. Docker Desktop на Windows обычно требует входа пользователя; Linux Server + Docker Engine + systemd надёжнее для полностью безоператорного запуска.
