# Исправление даты создания ВКС

## Что исправлено
- Поля `date` и `repeat_until` остаются календарными датами SQL DATE (`YYYY-MM-DD`), а не датой-временем с часовым поясом.
- Модель Meeting сериализует эти поля в JSON строго как `YYYY-MM-DD`, используя исходное значение атрибута SQL. Это предотвращает сдвиг на предыдущий день при преобразовании полуночи в UTC.
- Frontend нормализует исходящую дату без `toISOString()`; для объекта Date используются локальные компоненты календарной даты.
- Backend нормализует `date` и `repeat_until` до валидации и принимает их в строгом формате `Y-m-d`.
- Аналогичная строгая проверка добавлена для переноса встречи.

## Проверка после установки
1. Создать ВКС, выбрав, например, 05.11.2026.
2. В Network браузера открыть запрос POST `/api/meetings`: поле `date` должно быть `2026-11-05`.
3. Проверить SQL: `SELECT id, title, date FROM meetings ORDER BY id DESC LIMIT 5;` — дата должна быть `2026-11-05`.
4. Проверить ответ API и список встреч: `date` должен быть строкой `2026-11-05`, а интерфейс — показывать `05.11.2026`.

Старые записи не переписываются и миграция базы данных не требуется.
