# Автономный запуск BCS на Windows 10/11 + Docker Desktop

## Что обеспечивает
- После возврата электричества BIOS/UEFI включает компьютер (если поддерживает Restore on AC Power Loss).
- Windows запускается; после входа владельца Docker Desktop запускает Docker Engine.
- Задача планировщика Windows запускает `docker compose up -d` без пересборки образов.
- Watchdog каждые 5 минут проверяет контейнеры и поднимает остановленные/неисправные приложения.
- MySQL не перезапускается принудительно при одном только `unhealthy`: это защищает базу при медленном восстановлении или проблемах с диском.
- Laravel Scheduler уже создаёт проверяемую резервную копию БД ежедневно; копии находятся в Docker volume `db_backups`.

## Установка один раз
1. Убедитесь, что проект лежит в постоянной папке, например `D:\server\BCS`.
2. Запустите Docker Desktop и дождитесь `docker info`.
3. В Docker Desktop включите **Settings → General → Start Docker Desktop when you sign in**.
4. Откройте PowerShell от имени администратора и выполните:
   ```powershell
   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
   cd D:\server\BCS
   .\ops\windows\Install-Autostart.ps1
   ```
5. В BIOS/UEFI найдите `Restore on AC Power Loss`, `AC Back`, `After Power Failure` или похожий параметр и установите `Power On`.
6. Проверьте, что Windows автоматически входит в выделенную сервисную учётную запись или что Docker Desktop доступен после входа. Docker Desktop обычно не является полноценным unattended-сервисом до входа пользователя.
7. Проверьте задачи: `taskschd.msc` → Task Scheduler Library → `BCS - ...`.

## Проверка вручную
```powershell
.\ops\windows\Start-BCS.ps1
.\ops\windows\Watchdog-BCS.ps1
docker compose ps
docker compose logs --tail=100
```
Логи восстановления: `ops\logs\startup.log` и `ops\logs\watchdog.log`.

## Важное ограничение при отключении света
Без питания сервер не может продолжать работу. Чтобы не прерывать ВКС во время коротких отключений, нужен UPS для системного блока, дисков/роутера и сетевого оборудования. Подберите UPS по фактической нагрузке и желаемому времени автономии. Для длительных отключений нужен резервный интернет и электропитание. Настройте UPS на безопасное завершение Windows при низком заряде, а BIOS — на автоматическое включение после возврата питания.

Для полностью безоператорного запуска даже без входа в Windows надёжнее использовать Linux Server + Docker Engine как systemd-службу. Docker Desktop на Windows требует пользовательскую сессию и может не поднять движок до входа пользователя.

## Данные и безопасность
- Не используйте `docker compose down -v`.
- Не храните единственную резервную копию на том же физическом диске, что и MySQL.
- Настройте копирование проверенных `backup-*.sql.gz` на отдельный NAS/внешний диск/защищённое хранилище.
- Защитите учётную запись Windows, включите BitLocker, обновления безопасности и ограничьте доступ к RDP.

## Копия БД на отдельный диск или NAS
1. Откройте `ops\windows\backup-destination.txt`.
2. Укажите отдельный путь, например `E:\BCS-Backups` или `\\NAS\Backups\BCS` (сервисная учётная запись должна иметь права записи).
3. После ежедневного SQL-бэкапа в 02:30 задача в 03:45 копирует только архивы, SHA-256 которых совпадает с метаданными. На целевом диске хранится 30 дней.
4. Проверка вручную: `Copy-BCS-Backups.ps1`:
   ```powershell
   .\ops\windows\Copy-BCS-Backups.ps1
   ```

Если внешний диск отключён, задача запишет ошибку в `ops\logs\backup-copy.log`; основная резервная копия внутри Docker volume при этом не удаляется.
