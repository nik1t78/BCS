# BCS — единая консолидированная версия и аудит

Дата подготовки: 09.11.2026

## Что объединено

В основу взята автономная сборка от 07.11.2026. Сверены содержимое и состав файлов предыдущих архивов: `date-corrected-FINAL`, `next-day-dashboard-fixed`, `next-day-open-rooms`, `FAST-SECURE` и `FAST-SECURE-PLUS`. Все файлы этих версий присутствуют в итоговом дереве проекта. Восстановлены отсутствовавшие в автономном архиве статические файлы Font Awesome, на которые ссылается `index.html`.

## Дополнительные исправления 09.11.2026

1. В форме создания и редактирования ВКС начало и конец теперь округляются к ближайшим 30-минутным отметкам. Изменение начала автоматически задаёт конец +30 минут; изменение конца автоматически сдвигает начало −30 минут. Для полей времени установлен `step=1800`; минимальное время на сегодня и значение по умолчанию согласованы с получасовым шагом.
2. Исправлен Linux-установщик автономного режима: он копирует systemd unit-файлы в `/etc/systemd/system` перед `daemon-reload`. Раньше systemd не находил unit-файлы, лежавшие только в каталоге проекта.
3. Добавлен автозапуск опционального VKS-бота в Linux, если одновременно указаны `VKSBOT_EXPECTED=true` и `BOT_TOKENS`. Watchdog восстанавливает его, если контейнер был удалён/остановлен.
4. Windows watchdog также проверяет включение и конфигурацию бота и при необходимости поднимает его без пересборки образа.
5. Убрана принудительная политика сборки frontend при каждом `docker compose up`. Watchdog запускается каждые пять минут и не должен пересобирать frontend/нагружать компьютер. Обновление кода выполняется явно командой `docker compose up -d --build`.
6. Приведён к пустым значениям файл `backend/.env.example`: в нём больше нет слабых примерных паролей БД и Redis.

## Что не подтверждено запуском — обязательно учитывать

В среде подготовки отсутствуют Docker CLI/daemon, установленный полный набор Node-зависимостей и подключённая рабочая MySQL. `npm ci` не завершился из-за таймаута доступа к npm registry. Поэтому полный `npm run build`, `tsc --noEmit`, `docker compose build/up`, миграции на копии рабочей БД и браузерные E2E-тесты не выполнены. Не выполнялись реальные запросы к SaluteJazz, MAX/Push и тест отключения/возврата питания. Windows PowerShell/Task Scheduler также не доступны для исполнения установщика.

Это означает: исходники и конфигурации проверены статически, но проект нельзя честно объявить полностью протестированным в целевом окружении. Перед эксплуатацией нужно запустить архив на копии сервера/БД, выполнить миграции, проверить создание двух ВКС одновременно в разных залах, конфликт в одном зале, перенос, повторение, уведомления и реальную генерацию ссылки ботом.

## Важные условия автономной работы

- Для автоматического включения после восстановления электричества в BIOS/UEFI нужен параметр `Restore on AC Power Loss = Power On`.
- Для работы во время отключения нужен UPS для сервера и сетевого оборудования. Без питания программа работать не может.
- Для полностью безоператорного запуска предпочтителен Linux Server + Docker Engine + systemd. Windows + Docker Desktop зависит от входа пользователя в Windows.
- Для бота заполнить `BOT_TOKENS` и установить `VKSBOT_EXPECTED=true`; на Linux/Windows он поднимется автоматически. При пустом токене бот не стартует.
- Не выполнять `docker compose down -v`: команда может удалить постоянные тома с базой и данными.
