# Phase 39 — отложенная загрузка глобального поиска

## Что изменено

- Компонент глобального поиска больше не импортируется статически в `App.tsx`.
- Код поиска загружается отдельным chunk только при первом открытии панели поиска.
- Компонент обёрнут в `Suspense` с нейтральным fallback, чтобы интерфейс не мигал индикатором при первом открытии.
- Существующие горячие клавиши Ctrl+F / Cmd+F, поиск встреч, задач и сотрудников, права доступа и API не меняются.
- Frontend performance smoke test проверяет lazy import и наличие `Suspense`, чтобы не допустить возврата статического импорта.

## Почему это нужно

Глобальный поиск не нужен для первоначального отображения главной страницы. Его код и обработчики клавиатуры можно загрузить при первом использовании, не добавляя его в обязательную стартовую загрузку приложения.

## Границы

- Не меняются backend, API, авторизация, база данных и миграции.
- Не меняются `.env`, Docker volumes и существующие пользовательские данные.
- Изменение не обещает конкретного процента ускорения: фактический размер стартового chunk, LCP/INP и CPU нужно измерить в браузере и Docker после сборки.

## Проверки

GitHub Actions выполняет ESLint, TypeScript, frontend smoke checks и Vite production build. Это не заменяет ручную проверку поиска в браузере на desktop/mobile.
