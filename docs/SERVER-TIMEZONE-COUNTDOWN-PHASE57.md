# Phase 57 — время обратного отсчёта в часовом поясе сервера

## Проблема

Обратный отсчёт до ближайшей ВКС строил дату через `new Date("YYYY-MM-DDTHH:mm")`. Браузер интерпретирует такую строку в часовом поясе компьютера, тогда как расписание ВКС хранится в календарном времени сервера. При разных часовых поясах обратный отсчёт мог ошибаться на величину разницы между часовыми поясами.

## Исправление

- Добавлен `serverDateTimeToEpoch`: преобразует серверные дату и время в абсолютный timestamp с учётом IANA-часового пояса сервера.
- Обратный отсчёт главной страницы теперь использует эту функцию.
- Календарные поля главной страницы формируются из единого снимка серверного времени, поэтому день и часы не смещаются из-за часового пояса браузера.
- Проверяются некорректные календарные даты и значения времени, включая несуществующее локальное время при весеннем переходе на летнее время.
- Добавлена проверка календарной даты в браузерных поясах UTC, America/Los_Angeles и Asia/Tokyo.
- При невалидном значении часового пояса применяется безопасный резервный пояс `Europe/Moscow`.

## Проверки

Добавлен `scripts/server-timezone-countdown-smoke.mjs` и шаг CI. Проверяются Europe/Moscow, зимнее время Europe/Berlin, летнее время America/New_York и некорректные входные значения.

## Ограничения

Проверка выполняется на уровне преобразования времени и CI. Полный браузерный тест на реальном сервере и фактическая сверка с его `/api/time` требуют запуска целевого окружения.
