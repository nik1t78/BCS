# Phase 36 — производительность главной страницы

## Изменение

- Форма создания ВКС (UserPanel) больше не включается в стартовый граф зависимостей главной страницы.
- На главной форма загружается отдельным динамическим chunk только после выбора свободного слота или команды создания встречи.
- Пока chunk загружается, отображается компактный индикатор «Загрузка формы…».
- Тип MeetingPrefill остаётся type-only импортом и не добавляет runtime-зависимость.
- Существующий сценарий создания встречи, передача предзаполненных даты/времени/зала, обработчики закрытия и обновление списка встреч сохранены.

## Почему это важно

Ранее Dashboard.tsx импортировал UserPanel статически. Поэтому код большой формы создания конференции и её зависимостей мог попадать в загрузку главной страницы, даже когда пользователь только просматривал обзор. Теперь браузер получает этот код только при открытии формы.

## Проверки и ограничения

- Изменение локализовано в src/components/Dashboard.tsx; API, база данных, миграции, .env, Docker volumes и существующие данные не меняются.
- Нужно подтвердить production-сборку и typecheck в GitHub Actions.
- Реальный размер чанков, LCP/INP, CPU и сетевые запросы необходимо измерить в Docker/браузере на целевом сервере. Без такого замера численные улучшения не заявляются.
- Никакие PR не сливаются автоматически; production не обновляется.
