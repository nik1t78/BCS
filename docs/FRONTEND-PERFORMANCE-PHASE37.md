# Phase 37 — дополнительное разделение frontend-кода

## Что изменено

- Страницы расписания (`Schedule`) и профиля (`Profile`) переведены со статических импортов на `React.lazy`. Они загружаются при первом открытии соответствующих разделов.
- Модальное окно бронирования переговорной (`RoomBookingModal`) загружается только при открытии окна; пока chunk загружается, отображается доступный для скринридеров индикатор.
- Существующая ленивая загрузка `Dashboard`, `UserPanel`, `AdminPanel`, `Stats`, `Templates` и `TagsManager` сохранена.
- Добавлен smoke-check `scripts/frontend-performance-smoke.mjs`, который защищает границы code-splitting от случайного возврата к статическим импортам.
- Smoke-check добавлен в GitHub Actions после TypeScript typecheck.

## Совместимость

- Маршруты, props страниц, API-контракты, авторизация, бизнес-логика расписания и бронирования не менялись.
- Модальное окно по-прежнему получает дату, время, выбранный зал и прежние callbacks.
- Изменения не затрагивают БД, миграции, `.env`, Docker volumes и данные.

## Проверка

GitHub Actions должен подтвердить ESLint, TypeScript, frontend performance smoke-check и Vite production build. Фактическое уменьшение стартового JS bundle, LCP/INP и CPU необходимо измерить в браузере на целевой Docker-сборке. Численные улучшения заранее не заявляются.
