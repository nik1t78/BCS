# Phase 56 — стабильность рендеров главной страницы

## Исправление

Список встреч, доступных обычному пользователю на главной странице, ранее вычислялся через `filter()` непосредственно в теле компонента. Каждый рендер создавал новый массив. При этом эффект вычисления ближайших встреч зависел от этого массива и записывал новый массив в состояние. В результате эффект мог повторно запускаться после каждого рендера, создавая лишние обновления React и нагрузку на CPU.

Фильтрация перенесена в `useMemo`. Зависимости перечислены явно: список встреч, ID пользователя и его роль. Для администратора и модератора сохраняется исходный массив без дополнительной фильтрации.

## Регрессионная проверка

В `scripts/frontend-performance-smoke.mjs` добавлены проверки наличия memoization и корректных зависимостей. Проверка запускается в GitHub Actions вместе с остальными frontend smoke checks.

## Безопасность и границы

- Изменены только Dashboard и frontend smoke test.
- API, база данных, миграции, авторизация, `.env`, Docker volumes и пользовательские данные не затрагиваются.
- Изменение не публикуется на рабочем сервере автоматически.
- Фактическое снижение CPU необходимо подтвердить в браузере на целевом сервере после обновления.
